Karmen and I roleplay together. Dogs, cats, gems, whatever we're into that month. I build the systems we play in, and for a long time "sharing" one meant sending her a zip and a paragraph of instructions.

This month I got tired of that and decided to find out how real software gets onto someone else's computer. I have not had this much fun in ages.

Installers

The Warrior Codex is the app our cat game runs in. Its player app now has a proper Windows installer: a welcome page, Next, Finish, done. What I learned making it:

  • An installer can install for just one Windows user, which means no admin password and no "who is this for" page.
  • The uninstaller is part of the job. Mine asks whether to also delete your saved settings, and No is the default.
  • You can put your own art and your own words on the pages. Mine has a pixel dog. Pixel art only looks right at whole-number sizes, so he is drawn at 4x and 5x and never anything in between.
  • If you don't pay to sign your app, Windows warns people it's from an unknown publisher. Mine isn't signed, so the read-me says to click More info, then Run anyway.

I've made installers for three other things too: a notepad, a read-aloud app, and a Discord backup tool. The Python ones taught me a different lesson. The installer has to find or bring its own Python, and for the read-aloud app it picks the GPU or CPU version of the voice engine by itself. That one stays a folder and not a single exe, because the exe would be three or four gigabytes.

Updates that install themselves

Next I wanted to stop sending new copies at all. The player app checks a releases page on GitHub when it opens, downloads a new version in the background, and asks to restart. To do that I learned to keep two repos: a private one with the code, and a public one that holds nothing but the finished downloads.

I also learned that an app can't replace its own exe while it's running. Clack Attack taught me that the hard way. My first updater closed the app and then did nothing, because the little script meant to do the swap quit the instant it started. One version later it works, and anyone on the broken version had to download the fix by hand. Sorry about that.

The patcher

An updater is no help to someone whose copy is too old to have one. So there's a patcher: one exe, one big button. It says Install if you don't have the app, Update if you're behind, and Open if you're current. It carries an installer inside it so it works with no internet, and it can put an older version back if a new one misbehaves.

Then I did the same for my own side. Rebuilding everything used to mean a terminal full of scrolling text. Now it's a window with the dog, a progress bar, and the steps ticked off as they finish.

Everything else that came along

  • Git and GitHub. Commits, pushes, releases, and a .gitignore that keeps our worlds and save files off the internet.
  • Version numbers and changelogs. Every change gets a number and a note, and the old version is put away before I touch anything.
  • Backups. The Codex keeps copies of the world before it saves over it. Losing a whole cat saga to one bad save is not an option.
  • Sharing from my own PC. Players connect straight to my computer with a private key each. No server, no ports opened on the router.
  • Windows being Windows. Two kinds of line endings can quietly break a file. A window with no title bar still has to snap to the sides of the screen. Text in OBS gets measured one frame late.
  • Phones. I turned a web page into an Android app.

Why I'm this excited

The cat game went from version 1.2 to 6.25 in eight days. That is a silly number and I'm proud of it anyway.

What I like most is that none of this was the plan. I wanted to play pretend with Karmen and not have to say "okay, now unzip it, no, the other folder." Every skill on this page came from wanting that one thing to be easier. Now she double-clicks and the game opens.

Next I want to learn code signing, so Windows stops calling me an unknown publisher.
